# Data model

The SQL schema is defined in `backend/infrastructure/database/models.py` and versioned in `alembic/versions`.

| Table | Purpose | Important invariant |
|---|---|---|
| `rooms` | Authoritative current snapshot, phase, version, and expiry | Five-letter primary key; optimistic `revision` |
| `players` | Room membership and hashed expiring credentials | Case-insensitive name unique per room; token hash unique |
| `game_sessions` | Lifecycle timestamps for a room’s game | One session per room |
| `rounds` | Prompt and resolution state per round | `(room_code, number)` unique |
| `player_actions` | Durable submitted intentions | `(player, operation, idempotency_key)` unique |
| `game_state_snapshots` | Replay/debug checkpoints after committed versions | `(room_code, version)` unique |
| `results` | Immutable resolved-round outcome | `(room_code, round_number)` unique |
| `idempotency_records` | Exact response returned for retryable commands | `(player, operation, key)` unique |
| `game_events` | Privacy-safe ordered lifecycle facts | `(room_code, sequence_number)` unique |

The room JSON snapshot preserves the engine boundary while normalized records support auditing, indexing, cleanup, and later replay work. Event payloads contain public lifecycle facts only; private choices remain in access-controlled action/snapshot records.

## Migration workflow

```console
alembic revision --autogenerate -m "describe schema change"
alembic upgrade head
alembic downgrade -1
```

Inspect autogenerated migrations before committing. Test both upgrade and downgrade against a disposable database. Production application instances use `APP_ENV=production` and do not call `create_all`; the Compose `migrate` service must finish before the app starts.

## Retention

Idle rooms are marked expired rather than immediately deleted, preserving results and event history. Redis room markers expire automatically and are never a retention authority. Define an environment-specific archival/deletion policy before operating at scale.
